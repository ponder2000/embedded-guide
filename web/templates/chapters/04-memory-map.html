SECTION 01

One long ruler of addresses

A 32-bit CPU sees a single, unbroken line of addresses from 0x00000000 to 0xFFFFFFFF — over four billion of them. Nothing in that line is special by itself. What lives at each address is decided by how the chip is wired, and the designers carve the line into regions: flash here, RAM there, peripherals over here.

The big idea: there is exactly one address space, and everything plugs into it — code, data, and hardware alike. An address is just a number on the ruler; the silicon decides what answers when the CPU names it. These STM32-style bases (0x08000000, 0x20000000, 0x40000000, 0xE0000000) are worth memorising.
SECTION 02

Flash remembers, RAM forgets

Two physical memories share that ruler. Flash is slow-ish but non-volatile — it holds your firmware and constants across every power cycle. SRAM is fast but volatile — perfect for scratch values that only need to exist while the chip is awake. Each section of your program has a fixed home.

Notice the two memories grow toward each other inside RAM: the stack grows down from the top of SRAM as functions call functions, while the heap grows up from above your globals. They share one pool of free space, so a runaway recursion or a leaky allocator can quietly let them collide.

Why .bss costs no flash: a zero-initialised global has no value worth storing — startup code just zeroes that RAM region in a loop. Nonzero initial values must live in flash as the .data image and get copied into RAM before main() runs.
SECTION 03

When an address is a wire

Here is the trick that makes embedded magical: peripheral registers are not memory at all. They are circuits that happen to answer to an address. Write a value to the right address and you don't store a number — you change the physical world. A bit you set in a GPIO register becomes a voltage on a pin.

In this STM32F4-style example, 0x40020014 is GPIOA's Output Data Register. The cast (volatile uint32_t*) requests a 32-bit volatile hardware access; it does not make the address portable or add general memory barriers. With GPIOA clocked and PA5 configured as an output, writing 0x20 sets its output latch high—but also writes zero to the other ODR bits.

For STM32F4 GPIO, prefer the dedicated BSRR register: GPIOA->BSRR = (1u << 5); sets PA5, while GPIOA->BSRR = (1u << 21); resets it. Those writes do not read and rewrite the other output bits. Always check your exact device's reference manual; other STM32 families can use different addresses and configuration registers.

Memory-mapped I/O is the seam between software and the physical world. Once you accept that some addresses are wires rather than storage, the rest of embedded programming is just knowing which address does what — a question every chip answers in its reference manual.
