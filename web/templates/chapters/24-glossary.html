SECTION 01

The hardware vocabulary

Quick definitions, with links back to the lessons that build the full mental model. Addresses, electrical limits, and access rules always belong to an exact device—not to a generic term.

HardwareMemory and startupSignals and timingConcurrency and reliability
MCU · microcontroller
A chip integrating a processor core, memory, and peripherals for control applications. Meet the MCU →
CPU core
The instruction-executing engine, such as a Cortex-M4. Its name alone does not specify a chip's flash size or pinout. Core vs chip vs board →
Peripheral
A hardware function such as GPIO, a timer, or UART, usually controlled through registers. Accessing peripherals →
Datasheet / reference manual / errata
The datasheet specifies the device and electrical limits; the reference manual explains operation and registers; errata describe known limitations and workarounds. Find the right document →
Ground · GND
The circuit's voltage reference, not automatically earth ground or a promise of electrical safety. Signal connections need an appropriate common reference. Electrical essentials →
Pull-up / pull-down
A resistor or configured internal circuit that biases a released input toward a defined level. Strength, leakage, and capacitance affect behavior. GPIO input states →
SECTION 02

Memory and startup

MMIO · memory-mapped I/O
Peripheral registers occupy addresses in the processor's memory map; accessing them can cause hardware side effects. Memory maps →
Register / bit field
A hardware control or status location and a group of bits within it. Access width and read/write semantics matter as much as its address. Bits and registers →
W1C · write one to clear
A flag access rule where writing a one clears that flag. Blind read-modify-write can accidentally clear other set flags. Register access rules →
Flash / SRAM
Flash is nonvolatile storage commonly used for code; SRAM is volatile working memory. Their addresses, access properties, and capacities are device-specific. Memory regions →
Linker script / linker map
A script describes image placement and memory layout; a map reports where linked code and data ended up. Build artifacts →
Vector table / reset handler
On Cortex-M, the vector table supplies the initial stack pointer and handler entries. The reset handler establishes the runtime before application code. The boot sequence →
.data / .bss
Sections commonly holding initialized writable objects and zero-initialized objects. Startup copies initial .data values and clears .bss in RAM. Runtime initialization →
SECTION 03

Signals and timing

GPIO · general-purpose input/output
A configurable digital pin interface; mode, pulls, voltage tolerance, and alternate functions depend on the device. Talking to a pin →
Interrupt / ISR / NVIC
An interrupt requests exceptional execution; its interrupt service routine handles the event. The NVIC manages interrupt enable, priority, and pending state on Cortex-M. Interrupt handling →
Prescaler
A divider used to derive a slower clock. Register encodings may represent divisor minus one; consult the specific clock or timer. Clock derivation →
PWM · pulse-width modulation
A repeating pulse waveform whose active fraction is its duty cycle. Frequency and duty are different parameters. Timers and PWM →
UART / baud / 8N1
A serial interface; baud is symbol rate. Common 8N1 framing carries eight data bits, no parity, and one stop bit, plus a start bit: ten bit times per byte. UART frames →
SPI / I²C
Synchronous serial interfaces: conventional SPI uses clock, data, and chip select; I²C uses shared open-drain clock/data lines and addressed transactions. Comparing buses →
ADC / quantization / reference
An analog-to-digital converter maps an input to finite codes relative to a reference. Quantization is only one contributor to measurement error. Analog sampling →
Debouncing
Qualifying a noisy switch input before accepting a state transition. A recognized long press is a separate interpretation of a debounced state. Button filtering →
SECTION 04

Concurrency and reliability

Atomicity
An operation appears indivisible to the relevant observers. A load being atomic does not make a load-modify-store sequence atomic. Types, accesses, and races →
volatile
A language qualifier used for required observable accesses, including appropriate MMIO usage. It does not provide mutual exclusion, general inter-thread synchronization, or cache coherence. What volatile does →
DMA · direct memory access
A hardware engine moving data between supported endpoints without CPU instructions copying each unit. Buffers still need lifetime and ownership rules. DMA handoffs →
Watchdog
A timer requiring valid refresh behavior to avoid recovery, often a reset. Refresh should reflect useful progress, not merely an executing interrupt. Failure recovery →
RTOS / task / scheduler
A real-time operating system schedules tasks, each with execution context and usually its own stack. Task design still needs timing and resource budgets. RTOS fundamentals →
Queue / mutex
A queue transfers bounded items between contexts; a mutex provides ownership-based exclusion for a shared resource. Pointer messages still need buffer-lifetime rules. Communication and ownership →
Priority inversion
A higher-priority task waits on a resource held by lower-priority work. Priority inheritance can reduce some blocking but does not prevent deadlock. Priority and locking →
Latency / deadline / jitter
Latency is delay from event to response; a deadline bounds required completion time; jitter is variation in timing. Average speed alone does not establish any of them. Timing budgets →
