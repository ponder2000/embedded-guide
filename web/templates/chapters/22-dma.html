SECTION 01

Move data. Stop copying every byte.

Direct memory access lets a hardware engine move data between supported endpoints while the CPU does other work. A peripheral produces or consumes transfer requests; DMA moves configured units and reports progress or errors.

Read memory-mapped I/O, interrupts, and UART first. A UART receive register copied into a RAM buffer is a useful model, but peripheral request mappings and accessible memories are specific to the MCU.

DMA reduces CPU involvement per transferred unit; it does not eliminate bus traffic, latency, or software work. The CPU and DMA may compete for memory bandwidth. A slow consumer can still lose data.

SECTION 02

Configuration is a contract

  • Endpoints and direction: which peripheral register and which memory region? Is that region reachable by this DMA engine?
  • Transfer width and count: are units bytes, halfwords, or words? A count of 128 transfers is not always 128 bytes.
  • Increment: a UART data register commonly stays fixed while the RAM address advances.
  • Request mapping: select the documented stream/channel/request and the peripheral's DMA-request enable.
  • Mode and completion: choose normal, circular, or a supported double-buffer mode, and handle error status as well as success.

Validate alignment, buffer size, lifetime, and peripheral access width before enabling a transfer. Keep the buffer alive until the transfer is finished or safely cancelled. A stack buffer that goes out of scope while asynchronous DMA still uses it is a memory-lifetime bug, even if it appeared to work once.

Follow the device's order: configuration, flag clearing, request enable, and stream enable/disable sequences are not portable. Use the selected driver API or the exact reference manual, not an invented universal sequence.
SECTION 03

The hard part is ownership

For transmission, the CPU fills a buffer and hands it to DMA; it must not change those bytes until ownership returns. For reception, DMA fills a region and the CPU consumes it only after the relevant handoff. DMA transfer complete may mean the last value reached the peripheral register, not that a UART's final stop bit has left the pin: peripheral transmission-complete status answers that different question.

With a two-half circular receive buffer, half-transfer and transfer-complete notifications can identify regions that were just filled. They do not stop the DMA engine from wrapping around and overwriting a region later. The CPU must finish before reuse, or copy into separately owned storage. Define what happens if it cannot keep up: drop with a counter, apply supported flow control, or stop/restart through a documented recovery path.

On a cache-equipped MCU, CPU caches and DMA may not be coherent. Use suitable memory regions or the required clean/invalidate operations with cache-line alignment and ownership discipline. Do not invalidate cache lines containing unrelated dirty data. The STM32F401's Cortex-M4 core has no data cache, but that fact must not be generalized to other Cortex-M devices.

volatile does not establish buffer ownership, make an ISR handoff atomic, or perform cache maintenance. Ordering and synchronization requirements still apply; use your driver and target's documented mechanisms.

SECTION 04

Test throughput and overload

At 115200 baud with 8N1 framing, ideal payload throughput is 11520 bytes/s. A 128-byte region fills in about 11.1 ms under continuous traffic. In a circular buffer with two 128-byte halves, software has roughly one half-fill interval to finish a half before the next wrap begins reusing it—not an unlimited amount of time after the interrupt.

  • Verify a known pattern and exact transfer count, including partial and final transfers.
  • Delay the consumer deliberately and verify your overrun policy and diagnostic counters.
  • Test transfer errors, cancellation, and a restart without stale flags or invalid ownership.
  • Keep completion handlers short; notify foreground work or a task rather than parsing a large message in the ISR.

Official reference: use the DMA, bus architecture, and selected peripheral chapters of RM0368 from the STM32F401RE documentation. Request routing, transfer width, and available memory must match that exact device.
