SECTION 01

From a single bit to a whole byte

A bit is the smallest thing a computer can hold: just 0 or 1, off or on, low or high. Group four bits and you get a nibble; group eight and you get a byte — the unit almost everything in embedded is measured in. Each position in a byte carries a fixed power-of-two weight, and the value is simply the sum of the weights wherever a bit is set.

The core mechanic: a byte holds 256 distinct patterns (2⁸), so an unsigned byte counts 0 to 255. Reading one is pure addition — the high (left) bits are worth the most, the low (right) bits the least. Get comfortable here; every register, every address, every pixel of memory is just bytes wearing different labels.
SECTION 02

Hex: a compact shorthand for binary

Writing 10110100 by hand is error-prone — miscount one digit and you mean something else entirely. Hexadecimal fixes this elegantly: because one hex digit spans exactly four bits (a nibble), a whole byte collapses into just two tidy characters. Hex isn't a different kind of number, it's the same bits viewed four at a time.

The hex digits run 0–9 then A–F for the values ten through fifteen, covering all sixteen patterns a nibble can take. So 0xB4, 0b10110100, and decimal 180 are three spellings of one identical byte. The leading 0x is just C's way of saying "read what follows as hex."

This is why embedded code is drenched in hex. A 32-bit peripheral address like 0x40021000 or a config value like 0xFF00 maps cleanly onto the bit layout in the datasheet — each hex digit lines up with four bits of a register, so you can read field boundaries at a glance instead of squinting at thirty-two ones and zeros.
SECTION 03

Negative numbers and the wrap-around

Bits don't carry a minus sign, so how does a byte hold −1? The answer is two's complement: the most significant bit is repurposed as a sign, and the rest of the range folds around. It's the scheme nearly every CPU uses, because addition and subtraction "just work" on it with no special hardware.

Mechanically, to negate a number you flip every bit and add one: 1 is 0x01, its inverse is 0xFE, plus one is 0xFF — which is exactly how −1 is stored. The beauty is that ordinary binary addition of +5 and −5 overflows cleanly to zero, so the ALU needs no separate "subtract" logic.

Hardware patterns are not C arithmetic rules: the same byte represents 0..255 as a uint8_t or −128..127 as a two's-complement int8_t. Unsigned C arithmetic wraps modulo its width; signed overflow is undefined behavior, not a portable wraparound operation. Small integer types also undergo integer promotion before arithmetic. Choose the calculation width and the final storage type deliberately.
