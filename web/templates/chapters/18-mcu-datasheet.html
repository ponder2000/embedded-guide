SECTION 01

From architecture to board

A processor family is not a complete microcontroller specification. Learn which name answers which question before copying a register address or enabling a feature.

Learning objectives: distinguish architecture, instruction set, core, chip, and board; navigate a memory map; and choose the right document for a register operation.

An architecture specifies the programmer-visible machine: instructions, registers, exceptions, and memory behavior. Its instruction set architecture (ISA) describes the instructions and their encoding. A Cortex-M core is Arm's processor intellectual property implementing an architecture. A vendor integrates that core with flash, SRAM, clocks, and peripherals to make an MCU. A development board adds power, connectors, debugging hardware, and external components.

Cortex-M0 and M0+ implement Armv6-M; M3 implements Armv7-M; M4 and M7 implement Armv7E-M; M23 and M33 implement the Baseline and Mainline variants of Armv8-M, respectively. Cortex-M executes Thumb instructions, but supported subsets differ: do not assume every core supports every Thumb-2 instruction. DSP instructions, floating-point hardware, caches, and security features are not universal.

The STM32F401RET6 contains a Cortex-M4 with a single-precision FPU, an optional core feature that this device includes. It has 512 KiB flash and 96 KiB SRAM. Those capacities do not describe every STM32F401 variant, let alone every Cortex-M4 MCU. Match the full part number and package to the datasheet.

SECTION 02

Addresses locate bytes; bits select behavior

Flash retains firmware without power. SRAM holds working data while powered. Peripheral registers expose hardware controls through memory-mapped addresses; they are not ordinary storage. The STM32F401 maps flash at 0x08000000, SRAM at 0x20000000, and GPIOA at 0x40020000. Boot aliases can make another address refer to the selected boot memory.

A byte contains eight bits; 1 KiB is 1024 bytes, so 512 KiB is 524,288 bytes. A 32-bit register occupies four byte addresses, although the manual determines permitted access widths. Base-plus-offset arithmetic uses bytes, while a mask such as 1u << 5 selects bit 5 within a value.

Use C uint32_t, Rust u32, or Zig u32 for a documented 32-bit access. Register addresses must satisfy the device's alignment rules; arbitrary byte writes or misaligned pointers are not substitutes. STM32F401 uses little-endian data layout: a stored ordinary word 0x12345678 places byte 0x78 at its lowest address. Endianness does not change the manual's bit numbers.

SECTION 03

Choose the document that answers the question

  • Datasheet: exact device capacities, package pins, voltage limits, and electrical timing.
  • Reference manual: peripheral operation, register offsets, fields, and clock dependencies.
  • Programming manual or core guide: instructions, exception handling, and core registers.
  • Board schematic: actual wiring, LEDs, jumpers, connectors, and power paths.
  • Errata: silicon limitations and required workarounds for the relevant revision.

For PA5 on STM32F401, open reference manual RM0368. Find RCC's AHB1ENR and its GPIOAEN clock gate, then GPIOA's MODER: PA5 uses bits 11:10, with 01 selecting general-purpose output. Configure output type, speed, and pulls as appropriate. Follow the documented clock-enable delay/readback requirements before accessing GPIO. Finally locate BSRR, offset 0x18: bits 0–15 set corresponding outputs; bits 16–31 reset them.

The Nucleo schematic establishes whether PA5 actually drives LD2 on your board revision. A core guide cannot tell you that. Check pin multiplexing and board connections before claiming a register write will light an LED.

SECTION 04

Read the access rules before writing

A reset value describes the documented state after the specified reset, not a guarantee about the current state after startup code ran. RW means read/write; RO means read-only; W1C means writing one clears the corresponding flag. Read-modify-write on a W1C status register can accidentally clear unrelated pending flags. Reads can also have side effects.

Respect reserved-bit instructions and use documented masks. Read-modify-write may suit a normal configuration field, but can race with an interrupt modifying the same register. GPIO BSRR provides a hardware atomic bit action without a CPU read-modify-write; that does not make a whole multi-register configuration atomic.

Practical checkpoint: record your exact MCU, GPIOA base, BSRR offset, PA5 mode field, and clock-enable bit. Beside each, name the document that establishes it.
Self-check and answers

Does Cortex-M4 imply 512 KiB flash? No: the MCU part determines capacity. Is offset 0x18 a bit index? No: it is 24 bytes. Can you preserve W1C flags by writing back every read bit? No: ones would clear them.

Official starting points: STM32F401RE documentation and NUCLEO-F401RE board documents. Select the latest applicable revisions.
