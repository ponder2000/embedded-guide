SECTION 01

The chip wakes up at a fixed address

When power rises, the CPU has no concept of your program. It does exactly one thing it was hard-wired to do at the factory: read two words from the very start of flash. Those two words — the vector table — are the whole reason a cold chip ever finds your code.

On a Cortex-M, flash is mapped at 0x08000000, and the first entries of the vector table live right there:

  • Offset 0 — the initial Stack Pointer (where the stack will grow from).
  • Offset 4 — the address of Reset_Handler, the first instruction the CPU runs.
  • Offset 8 and up — one address per interrupt: NMI, HardFault, then every peripheral IRQ.
The key idea: the chip doesn't "look for" your program — it dutifully reads two fixed words and follows them. Get the vector table wrong (or place it at the wrong address) and the CPU jumps into garbage on the very first cycle.

SECTION 03

The startup code you never wrote

You almost never type the vector table or the .data/.bss loops by hand. Your toolchain ships them — a startup_*.s file and a linker script — generated for your exact chip. They quietly assemble the world before main() gets a single cycle.
