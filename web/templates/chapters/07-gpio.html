SECTION 01

A pin is a register bit in disguise

GPIO stands for General-Purpose Input/Output: a physical pin you can read or drive from software. Each pin is wired into a small stack of registers, and bending those bits is the entire job. Tell the pin which direction it faces, then either push a voltage out of it or sample the voltage coming in.

On an STM32, every pin belongs to a port (GPIOA, GPIOB, …) and each port is a cluster of 32-bit registers sharing one base address:

  • MODER — sets direction: two bits per pin choose input, output, alternate function, or analog.
  • ODR — the Output Data Register: one bit per pin holds the level you're driving when the pin is an output.
  • IDR — the Input Data Register: read-only, one bit per pin reflecting the actual voltage at the pad.
  • BSRR — Bit Set/Reset Register: write-only, the safe way to flip one ODR bit without a read-modify-write.
The mental model: a pin number is really a bit index. "Pin 5" means bit 5 of GPIOA's registers. Configure MODER once, then live in ODR (or BSRR) for the rest of your program.
SECTION 02

How a pin actually drives a wire

An output pin isn't magic — it's a pair of transistors. How they're arranged decides whether the pin can push both voltages or only pull one. Inputs get their own trick: internal resistors so a floating wire reads a defined level.

Push-pull uses two transistors so the pin can actively source a high and sink a low — perfect for driving an LED. Open-drain only has the lower transistor: it can pull the line to ground or let go, so it needs a pull-up resistor to reach a high. That shared-line behaviour is why I²C buses are open-drain. For inputs, STM32 offers internal pull-up or pull-down resistors (via the PUPDR register) so an unconnected pin reads a known 0 or 1 instead of floating noise.

Notice: SET and RESET don't read anything first — BSRR's low half-word sets bits, its high half-word resets them. One write, no race condition, even if an interrupt touches another pin in the same port mid-stride.
SECTION 03

The classic blink

Everything above collapses into the first program every embedded engineer writes: make an LED on PA5 blink. Configure the direction once, then flip one bit forever. This is "Hello, world" for bare metal.

Don't forget step zero: RCC->AHB1ENR gates each port's clock, and a port with no clock is deaf — writes silently do nothing. After that, MODER |= (1 << 10) writes 01 into the two-bit field for pin 5 (bits 11:10), choosing general-purpose output. From there the loop is pure bit-flipping.

Tying it together: every line here is the bitwise toolkit from earlier — |= to enable, a shifted mask to target one field, BSRR to set and reset without a read-modify-write. Master GPIO and you've learned the rhythm of every peripheral: read the datasheet, find the bits, flip them with intent.
